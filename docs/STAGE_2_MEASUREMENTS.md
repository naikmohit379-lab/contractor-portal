# Stage 2: India measurement workflow

For the current project-wide implementation status and next priorities, see [Implementation Status](IMPLEMENTATION_STATUS.md).

## Implemented foundation

- A user with the existing `measurement:order` permission can enter values from a third-party roof report or verified site measurement.
- Each report stores roof facets, pitch, linear measurements, waste allowance, optional imagery date, and a source note.
- Users enter values in the company's configured measurement system. Metric area and lengths are converted to the application's existing square-foot/foot storage before estimates consume them; existing U.S. records are unchanged.
- Manual entries are marked as such and included in the existing company-scoped audit log.
- Generated mock reports are labelled as sample data with a warning that they are not a real survey and must not be used for quotes or material orders.

## RoofV integration: adapter implemented, live ordering gated

RoofV's support response confirms India coverage and describes the output. The public [RoofV developer guide](https://roofv.ai/developers) and [OpenAPI document](https://roofv.ai/api/public/v1/openapi.json) describe the API contract. The account-specific email says Bengaluru and other metros have been tested, and recommends GPS/map-pin coordinates because Indian street addresses can resolve imprecisely. The OpenAPI spec also recommends sending coordinates outside the US/Canada.

Confirmed API facts: base URL `https://roofv.ai/api/public/v1`; API key from RoofV **Settings → API**; `GET /me` is a free authentication/quota check; `POST /measurements` can accept GPS coordinates, address label, and pitch; RoofV supports `measurement.reviewed` webhooks; results carry sqft and metric values. Measurement requests consume the included allowance or credits, so this code must not issue live requests during development checks.

The integration code is present behind `ROOFV_ENABLED=false` by default. It provides a server-side adapter, India-only ordering, map-coordinate capture on job creation or the Measurements tab, a per-request disclosure and consent checkbox, a pitch field, and background reads while the page is open for pending reports. The API key is read only by the backend from `ROOFV_API_KEY`; it is never sent to the browser. New report reads use RoofV's free `GET /measurements/{roof_id}` endpoint and are spaced at least five minutes apart. If a lookup times out, the existing report remains recoverable; the UI offers a free read retry that does not order another measurement. RoofV does not support arbitrary idempotency headers, so the UI warns users not to blindly retry a timed-out order request.

The Measurements tab also has a **Check RoofV free quota** action. It calls RoofV's free `GET /me` endpoint from the server and returns only the sanitized monthly quota/credit fields; account identity and key abilities are not exposed. The check sends no property address or coordinates and does not order a measurement. It requires an authenticated user with `measurement:order` permission. **Refresh existing RoofV report** performs only a free GET against the already stored `roof_id` (including for delivered reports); it cannot create another measurement order.

Staging validation on 2026-10-31: RoofV `/me` showed 30 included measurements and 0 prepaid credits. One authorized Koramangala sample order returned 110.93 m² and `review.status: not_reviewed`; the app correctly marks it preliminary. The supplied 6/12 pitch was the Roofora default/input, not a satellite-derived pitch. The RoofV response did not contain edge lengths or an imagery date, and the UI now displays those as unavailable. The initial report read timed out through the saved RoofV job endpoint; the code was corrected to use the vendor-documented free `/measurements/{roof_id}` lookup, and the existing request was recovered without issuing another order. A later quota check still showed 30 included and 0 prepaid credits; confirm any quota attribution in the RoofV account before using measurements beyond this sample.

Before enabling production calls:

1. Create a dedicated, expiring Roofora API key with write permission, then keep it only in Vercel Preview/server environment variables. Never paste it into chat, commit it, or expose it to the browser.
2. Keep `ROOFV_API_KEY` and `ROOFV_ENABLED` in Vercel Preview only until validation is complete. The Preview environment-variable entries are present, but their secret values cannot be verified from repository metadata. Use the free quota check to verify the key and quota before requesting any measurement.
3. Confirm the account's current trial/plan limits and concurrency with RoofV before testing real measurements. The vendor's email gives plan prices and a two-request concurrency limit; treat those as account-specific until confirmed in the RoofV account.
4. Verify a real India address only after the implementation is in Preview and the user explicitly chooses to send that property's address/coordinates. The API has no separate sandbox according to the vendor email.

Never commit or paste provider credentials into source control or chat. Production remains disabled until Preview validation succeeds and the user explicitly authorizes enabling it.

## Current limitations

- Manual entry is not a RoofV import. The user transcribes values from the vendor's report.
- The application stores normalized area and lengths in its existing internal units; the UI converts them based on company settings.
- RoofV image attachments are not stored by this flow. Original report PDF retrieval is implemented automatically when RoofV supplies its saved-job ID; manual PDF upload is intentionally excluded.
- RoofV's signed webhook is not implemented. Pending-report refresh runs while a user is viewing the Measurements tab; a signed webhook or scheduled job for unattended reports is still not configured.
- RoofV response normalization handles documented fields but still needs comparison with the account's real response before results are used in estimates. Treat all RoofV outputs as requiring verification.
- Ambiguous RoofV buildings currently return an error; choosing and resubmitting a candidate is not implemented.
- **Original RoofV report PDF retrieval implemented in source:** After fetching RoofV measurement data, the server automatically requests the PDF from RoofV's saved-job report endpoint when a RoofV job ID is available. It validates the PDF signature and 15 MB limit, stores it privately with SHA-256 and retrieval metadata, and records an audit event. Authorized users download it through the authenticated Measurements tab. Manual PDF upload is intentionally excluded. If RoofV has not published the PDF yet or no saved-job ID was returned, the measurement stays usable without a PDF; a later free refresh can retry retrieval. Measurement values are unchanged.
